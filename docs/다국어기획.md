# Aroon 다국어(i18n) 시스템 기획

## 1. 개요

지원 언어: **한국어(ko)**, **영어(en)**, **중국어(zh)**

다국어가 필요한 영역:
- **정적 텍스트**: API 응답 메시지, 에러 메시지, 유효성 검증 메시지
- **동적 콘텐츠**: 메뉴 이름, 역할 이름, 권한 이름 등 DB에 저장되는 데이터

---

## 2. 방안 비교

### 방안 A: Spring MessageSource (Properties 파일)

모든 텍스트를 `.properties` 파일에서 관리하는 방식

```
src/main/resources/
├── messages.properties          # 기본 (한국어)
├── messages_en.properties       # 영어
└── messages_zh.properties       # 중국어
```

```properties
# messages.properties (기본 - 한국어)
user.not.found=사용자를 찾을 수 없습니다
login.failed=아이디 또는 비밀번호가 올바르지 않습니다

# messages_en.properties
user.not.found=User not found
login.failed=Invalid username or password

# messages_zh.properties
user.not.found=找不到用户
login.failed=用户名或密码不正确
```

| 평가 항목 | 점수 | 설명 |
|-----------|:----:|------|
| 개발효율 | ★★★★★ | Spring 기본 내장, 설정 간단, 코드 변경 최소화 |
| 운영효율 | ★★★☆☆ | 메시지 변경 시 재배포 필요 |
| 확장성 | ★★★☆☆ | 언어 추가는 파일만 추가하면 됨, 동적 콘텐츠 불가 |

**적합한 용도**: 에러 메시지, 유효성 검증 메시지, API 응답 메시지 등 정적 텍스트

### 방안 B: DB 번역 테이블 (공통 번역 테이블)

모든 번역을 하나의 공통 번역 테이블에서 관리

```sql
CREATE TABLE `translation` (
    `translation_seq` BIGINT NOT NULL AUTO_INCREMENT,
    `table_name`      VARCHAR(50)  NOT NULL COMMENT '대상 테이블명',
    `column_name`     VARCHAR(50)  NOT NULL COMMENT '대상 컬럼명',
    `record_seq`      BIGINT       NOT NULL COMMENT '대상 레코드 SEQ',
    `locale`          VARCHAR(10)  NOT NULL COMMENT '언어 코드 (ko, en, zh)',
    `value`           TEXT         NOT NULL COMMENT '번역된 값',
    PRIMARY KEY (`translation_seq`),
    UNIQUE KEY `uk_translation` (`table_name`, `column_name`, `record_seq`, `locale`),
    KEY `idx_translation_lookup` (`table_name`, `record_seq`, `locale`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='다국어 번역';
```

```sql
-- 예시: 메뉴 이름 다국어

(5, 'menu', 'menu_name', 2, 'en', 'User Management'),

-- 예시: 역할 이름 다국어

(8, 'role', 'role_name', 1, 'en', 'Administrator'),
(9, 'role', 'role_name', 1, 'zh', '管理员');
```

| 평가 항목 | 점수 | 설명 |
|-----------|:----:|------|
| 개발효율 | ★★★☆☆ | 번역 조회 로직 추가 필요, 공통 유틸 한번 만들면 재사용 |
| 운영효율 | ★★★★★ | 재배포 없이 DB에서 번역 추가/수정, 관리 화면으로 운영 가능 |
| 확장성 | ★★★★★ | 어떤 테이블이든 번역 가능, 새 언어 추가 시 데이터만 추가 |

**적합한 용도**: 메뉴명, 역할명, 권한명 등 운영 중 변경 가능한 동적 콘텐츠

### 방안 C: 엔티티 내 로케일 컬럼 방식

각 테이블에 언어별 컬럼을 직접 추가

```sql
CREATE TABLE `menu` (
    `menu_seq`    BIGINT NOT NULL AUTO_INCREMENT,
    `menu_name_ko` VARCHAR(100) NOT NULL COMMENT '메뉴 이름 (한국어)',
    `menu_name_en` VARCHAR(100) NULL COMMENT '메뉴 이름 (영어)',
    `menu_name_zh` VARCHAR(100) NULL COMMENT '메뉴 이름 (중국어)',
    ...
);
```

| 평가 항목 | 점수 | 설명 |
|-----------|:----:|------|
| 개발효율 | ★★★★☆ | 조인 불필요, 단순 조회, 코드 간단 |
| 운영효율 | ★★☆☆☆ | 언어 추가 시 ALTER TABLE 필요, 모든 테이블 수정 |
| 확장성 | ★★☆☆☆ | 언어 추가마다 스키마 변경, 컬럼 폭발 위험 |

**적합한 용도**: 언어 수가 확정되고 변경 가능성이 낮은 경우 (비추천)

### 방안 D: JSON 컬럼 방식

-- 데이터 예시
-- menu_name: {"ko": "시스템 관리", "en": "System Management", "zh": "系统管理"}

| 평가 항목 | 점수 | 설명 |

## 4. 추천: 하이브리드 방식 (A + B)

**정적 텍스트는 MessageSource, 동적 콘텐츠는 DB 번역 테이블**로 이원화

```
┌──────────────────────────────────────────────────────────────┐
│                    다국어 시스템 구조                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  [정적 텍스트]                [동적 콘텐츠]                    │
│  Spring MessageSource        DB Translation 테이블            │
│                                                              │
│  - API 응답 메시지            - 메뉴 이름                      │
│  - 에러 메시지                - 역할 이름                      │
│  - 유효성 검증 메시지          - 권한 이름                      │
│  - 시스템 안내 문구            - 코드성 데이터의 표시명          │
│                                                              │
│  properties 파일 관리         DB + 관리 화면으로 관리            │
│  서버 메모리 캐싱              Redis 또는 로컬 캐싱             │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 5.1 정적 텍스트 (Spring MessageSource)

#### 파일 구조
```
src/main/resources/
├── i18n/
│   ├── messages.properties          # 기본 (한국어)
│   ├── messages_en.properties       # 영어
│   └── messages_zh.properties       # 중국어
```

#### MessageSource 설정
```java
@Configuration
public class MessageConfig {

    @Bean
    public MessageSource messageSource() {
        ReloadableResourceBundleMessageSource source = new ReloadableResourceBundleMessageSource();
        source.setBasename("classpath:i18n/messages");
        source.setDefaultEncoding("UTF-8");
        source.setCacheSeconds(60);
        return source;
    }

    @Bean
    public LocaleResolver localeResolver() {
        AcceptHeaderLocaleResolver resolver = new AcceptHeaderLocaleResolver();
        resolver.setDefaultLocale(Locale.KOREAN);
        resolver.setSupportedLocales(List.of(
            Locale.KOREAN,
            Locale.ENGLISH,
            Locale.CHINESE
        ));
        return resolver;
    }
}
```

#### 사용 방법
```java
// 클라이언트 요청 헤더로 언어 결정
// Accept-Language: ko    → 한국어
// Accept-Language: en    → 영어
// Accept-Language: zh    → 중국어

// Service에서 사용
@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final MessageSource messageSource;

    public UserResponse getUserBySeq(Long userSeq, Locale locale) {
        User user = userMapper.selectById(userSeq);
        if (user == null) {
            String message = messageSource.getMessage("user.not.found", null, locale);
            throw new BusinessException(ErrorCode.USER_NOT_FOUND, message);
        }
        return toResponse(user);
    }
}
```

CREATE TABLE `translation` (

#### 번역 조회 공통 유틸리티

```java
@Component
@RequiredArgsConstructor
public class TranslationHelper {

    private final TranslationMapper translationMapper;

    /**
     * 단일 번역 조회
     */
    public String translate(String tableName, String columnName, Long recordSeq, String locale) {
        Translation translation = translationMapper.findTranslation(
            tableName, columnName, recordSeq, locale
        );
        if (translation != null) {
            return translation.getValue();
        }
        // fallback: 기본 언어(ko)로 조회
        Translation fallback = translationMapper.findTranslation(
            tableName, columnName, recordSeq, "ko"
        );
        return fallback != null ? fallback.getValue() : null;
    }

    /**
     * 특정 테이블의 특정 컬럼에 대한 번역 일괄 조회
     * (N+1 문제 방지)
     */
    public Map<Long, String> translateBatch(String tableName, String columnName,
                                             List<Long> recordSeqs, String locale) {
        List<Translation> translations = translationMapper.findTranslations(
            tableName, columnName, recordSeqs, locale
        );
        return translations.stream()
            .collect(Collectors.toMap(Translation::getRecordSeq, Translation::getValue));
    }
}
```

#### Service에서 사용 예시

```java
@Service
@RequiredArgsConstructor
public class MenuServiceImpl implements MenuService {

    private final MenuMapper menuMapper;
    private final TranslationHelper translationHelper;

    @Override
    public List<MenuResponse> getAllMenus(String locale) {
        List<Menu> menus = menuMapper.selectList(null);
        List<Long> menuSeqs = menus.stream().map(Menu::getMenuSeq).toList();

        // 번역 일괄 조회 (N+1 방지)
        Map<Long, String> nameMap = translationHelper.translateBatch(
            "menu", "menu_name", menuSeqs, locale
        );

        return menus.stream().map(menu -> MenuResponse.builder()
            .menuSeq(menu.getMenuSeq())
            .menuName(nameMap.getOrDefault(menu.getMenuSeq(), menu.getMenuName()))
            .menuCode(menu.getMenuCode())
            .path(menu.getPath())
            .build()
        ).toList();
    }
}
```

## 6. 성능 최적화: 캐싱 전략

번역 조회가 매 요청마다 DB를 치면 성능에 영향이 있으므로, 캐싱을 적용합니다.

### 6.1 캐싱 구조

```
요청 → 로컬 캐시 (ConcurrentHashMap) → DB
         (Hit)                      (Miss)
         즉시 반환                   DB 조회 → 캐시 저장 → 반환
```

### 6.2 캐시 키 설계

```
캐시 키: "translation:{table_name}:{column_name}:{record_seq}:{locale}"
예시:    "translation:menu:menu_name:1:en"
```

### 6.3 캐시 갱신 정책

| 이벤트 | 캐시 처리 |
|--------|----------|
| 번역 등록/수정 | 해당 키 캐시 삭제 (갱신) |
| 번역 삭제 | 해당 키 캐시 삭제 |
| 서버 시작 | 전체 번역 로딩 (Warm-up) |
| TTL 만료 | 자동 갱신 (10분 권장) |

## 8. 구현 로드맵

| 단계 | 작업 | 우선순위 |
|------|------|----------|
| 1 | MessageSource 설정 + 3개 언어 properties 파일 생성 | 높음 |

| 5 | TranslationHelper 공통 유틸리티 구현 | 중간 |
| 6 | 메뉴/역할/권한 Service에 번역 조회 적용 | 중간 |
| 7 | 번역 캐싱 적용 | 낮음 |
| 8 | 번역 관리 API 및 화면 구현 | 낮음 |

## 9. 핵심 결정 사항 요약

| 결정 사항 | 선택 | 이유 |
|-----------|------|------|
| 정적 텍스트 다국어 | Spring MessageSource | 개발 효율 최고, Spring 내장 |
| 동적 콘텐츠 다국어 | 공통 번역 테이블 (translation) | 운영 효율 + 확장성 최고 |
| 언어 감지 방식 | Accept-Language 헤더 | REST API 표준, 클라이언트 자유도 |
| 기본 언어 | 한국어 (ko) | 주 사용자 기반 |
| Fallback 정책 | 해당 언어 없으면 → 한국어 | 번역 누락 시 안전 |
| 캐싱 | 로컬 캐시 (추후 Redis 확장 가능) | 초기 단순성, 확장 가능 |
